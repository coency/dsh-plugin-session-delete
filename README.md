# dsh-plugin-session-delete

中文 | [English](README.en.md)

给 **DeepSeek Harness (DSH)** 补上官方不提供的**删除会话**能力：侧栏每个会话行的 `...` 菜单里多一个
「删除会话」，确认后即可把某个已存储会话连同它的注册表引用一起彻底清掉。

> DSH 本身只提供**归档**；清理已存储会话属于官方文档所说的"带外维护"（out-of-band maintenance）。
> 本插件把这件事自动化，并且顺序正确：**先经官方写链摘除注册表引用，再删存储文件**，
> 因此不会留下"内存把已删 id 写回文件"的脏数据。

## ⚠️ 删除前请先看

> **前提**：视图选项里的会话筛选要选 **「全部对话（显示已归档）」**，否则已归档的会话看不见，也就无从删除。

**判据只有一个：宿主此刻有没有为这个会话运行中的 agent。**

| 「永久删除」按钮 | 含义 | 怎么做 |
|---|---|---|
| **可点** | 宿主没有为它运行 agent | 直接点「永久删除」，删除后立刻从侧栏消失 |
| **置灰（禁用）** | 宿主正占用它（里面有 agent 或后台任务在跑） | 先点「**归档会话**」停掉它的工作，再点「**删除会话**」——按钮恢复可用 |

**在这个判据之外，还有几条规则要知道：**

1. **与“用了多久”“多久没用”无关**：只看宿主此刻有没有为它运行 agent。
2. **归档 ≠ 释放内存**：归档只是**停掉它的工作**，宿主仍把它记在内存里。所以已归档的会话能删，但**删除后侧栏会留一条**（在「全部对话（显示已归档）」里看得到）——那只是列表里的残留，**不用管它，重启 DSH 后自动消失**。
3. **重启 DSH 会让所有会话回到“没有 agent 在跑”的状态**：如果有一批会话都删不掉，重启后再删最省事。
4. **分组不影响删除**：工作区只是分组记录，**删除工作区不会删除会话文件**，那些会话会进入「未分组」；它们能否删除，仍按上表判断。
5. **删除不可恢复、不保留备份。**

## 安装

**桌面端（DeepSeek Harness 应用）**

在「插件 → 添加插件」里填入：

```
github:coency/dsh-plugin-session-delete
```

安装完成后**完全退出应用再重新打开**（宿主半侧的代码只在启动时加载）；重启后侧栏任意会话行的 `...`
菜单里就有「删除会话」。

**网页端 / 命令行（`dsh plugin`）**

```bash
dsh plugin --profile web add github:coency/dsh-plugin-session-delete
dsh web
```

若 profile 是 `patchReload: live`，重启后无需任何额外操作，侧栏菜单即刻可用。

> 本包声明了 `dsh.bundle.patch`，插件管理器会把它作为组合包安装并默认启用；需要固定版本时在地址后加 `#v0.2.8`。

## 用法

鼠标悬停侧栏任意会话行 → 点 `...` → 选「删除会话」→ 确认框会实时向宿主查询"将删除几个目录、
释放多少空间"，点「永久删除」才真正执行。

**不可恢复，也不保留备份。**

## 删除做了什么

1. **先动注册表**（经 workspace domain 写链，内存与磁盘同时更新）：摘掉该会话在工作区成员、归档集合、
   置顶集合里的引用；
2. **再删文件**：`$DSH_HOME/sessions/<project>/<id>/` 与会话投影缓存记录；项目目录空了顺手删掉。

## 已知限制

- **删除不可恢复**，不做备份（刻意的：备份会让"删除"变成两处存储状态）。
- **未归档的活动会话删不掉**：宿主仍持有它的写入句柄 → **先归档它**（DSH 的归档动作会先停掉该会话的工作），然后再删——**不需要重启 DSH**。
- **已归档的会话可以直接删**：即使它仍在宿主内存里（DSH 会把已归档会话保留到进程退出）。万一宿主退出时把内存里的内容补写了一次、目录又出现了，再删一次即可——那时它已不在内存中。
- **子代理会话**的目录名是裸 UUID（不含 `session-` 前缀），本插件两种拼写都接受。
- **宿主插件不受工作区沙箱限制**：它需要删除 `$DSH_HOME` 下的文件，代码很短、可审计。
- **同一会话不能并发删除**：若同一会话已有一个删除在执行（比如你点了删除、agent 同时也在删它），第二个请求会立即返回"正在被删除"，等第一次结束后重试即可。
- **投影缓存的历史整卷文件不处理**：该会话的按记录缓存（`storages/session_projcache/sessions/<id>.json`）会被删除，但旧格式的整卷文件 `storages/session_projcache.json` 本插件不动。DSH 只在缺少按记录文件时才会从整卷文件重建记录，且会做身份校验，因此重建出来的旧记录不会再被采用。

## 版本兼容

本插件依赖 DSH 的**内部约定**（不是公开的插件 API），已在 **dsh 0.1.7-rc.2**（Web profile、Windows）
实测通过。DSH 处于 rc 阶段，升级后若侧栏菜单项消失或删除报错，就是某个内部约定变了——这类修复通常只有
几行，可对着新版 DSH 的包源码调整。

刻意**不声明任何 DSH peer 依赖**：写死版本会让未来版本必须逐个走"版本豁免"，反而抬高安装门槛。

## 卸载

**桌面端**：在「插件」页里卸载本插件，然后**完全退出应用再重新打开**。

**网页端 / 命令行**：

```bash
dsh plugin --profile web remove dsh-plugin-session-delete
```

卸载后要**重启一次 DSH**，并刷新浏览器页面：

- 运行中的宿主进程可能仍持有**已加载的插件模块**——删掉文件、移除加载行都不足以让它卸载，只有重启进程才会
  真正卸下（这也是本插件安装后需要重启的同一个原因）；
- 浏览器里已经加载过的那份 bundle 同样要等页面刷新才会消失，否则侧栏可能还留着「删除会话」入口；
- 若 profile 是 `patchReload: live`，宿主侧通常会在卸载后即刻重组，但**重启仍是最可靠的做法**。

数据不会被恢复：已删除的会话就是删除了。
